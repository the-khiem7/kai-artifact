AWS Lambda Web Functions

Mô hình lập trình và deploy

Độ tin cậy: cao (3-0).

  • Deploy bằng file .zip. Lambda tạo HTTPS endpoint, quản lý execution environment và scale theo traffic, kể cả về 0.
  • Dùng framework Node.js quen thuộc (Express, Hono, React Router) mà không cần adapter hay wrapper riêng của Lambda.
  • Server phải bind vào host và port trong biến môi trường AWS_LAMBDA_HTTP_ENDPOINT (dạng host:port).
  • Runtime nạp index.js ở gốc package, hoặc file chỉ định bởi AWS_LAMBDA_NODEJS_ENTRYPOINT.
  • Lambda không kiểm tra server có thực sự đã lắng nghe hay chưa.
  • Next.js ở chế độ standalone cần một index.js nhỏ để đặt host và port.

Bài Classmethod (bản phân tích trước ra mắt) ghi port 3000 và trả 502 với port khác. Tài liệu chính thức nay dùng port lấy từ AWS_LAMBDA_HTTP_ENDPOINT, nên hãy đọc biến môi trường thay vì hardcode port.

Concurrency và cold start

Độ tin cậy: cao (3-0), kèm lưu ý về con số.

  • Tham số maxConcurrencyPerEnvironment: mặc định 64, tối đa 128.
  • AWS nói cách này giảm cold start "orders of magnitude". Đây là ngôn ngữ tiếp thị, chưa có benchmark độc lập.
  • Request vượt giới hạn nhận HTTP 429 và không được xếp hàng. 429 cũng có thể đến từ các cấu hình maxEnvironments và rateLimit ở cấp endpoint.

64 và 128 là mặc định và trần của một giới hạn được quản lý động, nên concurrency duy trì thực tế có thể thấp hơn. Compute và memory dùng chung giữa các request đồng thời, nên một request nặng CPU có thể làm chậm các request khác.

Mô phỏng: cần bao nhiêu execution environment?

Mô hình lý tưởng hóa: Event Functions cần một environment cho mỗi request đồng thời, Web Functions cần ceil(request / giới hạn mỗi environment). Giới hạn thực tế do Lambda điều chỉnh động và có thể thấp hơn giá trị bạn chọn, nên đây là cận dưới. Không mô phỏng maxEnvironments, rateLimit hay 429.

Mặc định tái hiện ví dụ của pricing page: request mở 3.000 ms, active CPU 200 ms. Giả định mỗi request dùng 1 vCPU trong lúc hoạt động. Không gồm memory (tính theo vòng đời environment, phụ thuộc cấu hình và độ lấp đầy), free tier và data transfer. Dùng đơn giá US East (N. Virginia), Arm.

Độ tin cậy: cao, nhưng chủ yếu dựa trên một trang tài liệu chính (web-functions-networking).

CloudFront là cổng trước được tài liệu hướng dẫn cho custom domain, cache, nén, WAF và HTTP/2, HTTP/3. Các tính năng này chỉ áp dụng giữa viewer và edge, chặng origin vẫn là HTTP/1.1.

Egress (chiều ra) và VPC

  • Web Function không chạy trong VPC của bạn. Connector chỉ thêm đường ra, không làm endpoint thành private và không giới hạn request đi vào.
  • Connector tham chiếu bất biến theo revision: muốn đổi connector phải tạo revision mới.
  • Connector chỉ dùng được với endpoint HomeRegion. Endpoint MultiRegion hoặc PerRegion bị từ chối.
  • Connector cần compute resource type là WebFunction và ít nhất hai subnet ở hai AZ khác nhau. IPv6 cần connector DualStack, subnet có IPv6 CIDR và route ::/0.

Multi-Region và streaming

Độ tin cậy: trung bình, vì các số liệu streaming đến từ tài liệu streaming chung của Lambda.

  • Deploy một lần trên nhiều Region sau một endpoint, Lambda định tuyến theo độ trễ (best-effort) tới Region gần người dùng nhất. URL toàn cầu có dạng <domain-id>.lambda-web.global.on.aws, được thiết lập tự động bằng --regions.
  • Nếu scale về 0, request có thể phải chờ environment khởi tạo.
  • Response streaming của Lambda nói chung cho payload tới 200 MB (so với 6 MB khi buffer) và cải thiện time to first byte. Băng thông không giới hạn cho 6 MB đầu, sau đó khoảng 2 MBps.
  • Streaming truy cập được qua function URL, InvokeWithResponseStream hoặc tích hợp proxy của API Gateway.

Claim "managed runtime chỉ hỗ trợ streaming cho Node.js" đã bị bác bỏ (1-2) trong khâu kiểm chứng, đừng khẳng định điều này.

Quan hệ với Lambda Web Adapter

Độ tin cậy: trung bình, chỉ dựa trên README của aws-lambda-web-adapter.

  • Adapter chạy một app HTTP không sửa đổi trên Lambda, dưới dạng binary tại /opt/extensions/lambda-adapter trong Docker image, hoặc layer cho gói zip với AWS_LAMBDA_EXEC_WRAPPER=/opt/bootstrap.
  • README khuyến nghị dùng Web Functions cho app Node.js mới.
  • Với runtime khác và container image, tiếp tục dùng Web Adapter cho tới khi Web Functions hỗ trợ native.

Lưu ý về độ tin cậy và câu hỏi mở

  • Tính năng mới được 2 ngày. Mọi nguồn chính đều là first-party AWS, chưa có benchmark hoặc báo cáo production độc lập.
  • Các câu như "giảm cold start orders of magnitude" và "có thể giảm chi phí" là ngôn ngữ tiếp thị, chưa định lượng.
  • Giá chỉ cho US East (N. Virginia) trên Arm và có thể đổi. Một con số 2 vCPU / 2 GB cho mỗi environment xuất hiện trong ghi chú của một agent kiểm chứng, nhưng chưa được xác nhận độc lập, nên không đưa vào bảng.
  • Các số liệu streaming (200 MB, các đường invoke) đến từ tài liệu response streaming chung, không phải trang riêng của Web Functions.

Câu hỏi còn mở

  • Active CPU time được đo thế nào (cách lấy mẫu, mức tối thiểu, hành vi khi 128 request chia sẻ CPU)? Giá x86 và các Region khác là bao nhiêu?
  • Khi nào có Python, Java, .NET hoặc container image? Danh sách Region có mở rộng không?
  • Số đo thực tế về cold start, độ trễ và chi phí so với Event Functions, Lambda Web Adapter, Fargate và App Runner cho SSR và AI streaming?
  • Egress connector có thể kết hợp với endpoint MultiRegion hoặc PerRegion trong tương lai không? Hiện tại truy cập data store private trong multi-Region nên làm thế nào?

Định nghĩa và vị trí của Web Functions (cao, 3-0)
What's New (12/10/2026): "a new serverless compute primitive where your code handles HTTP requests directly". News Blog: "a new form factor that lets you run standard HTTP web applications on Lambda". Compute Blog (13/10): "your code runs as a standard HTTP server that listens on a port".

Concurrency (cao, 3-0)
What's New: "A single warm execution environment can serve multiple concurrent requests". News Blog: tối đa 128 request đồng thời mỗi environment. Compute Blog: mặc định 64, environment Event Function phục vụ một request một lúc và bị freeze giữa các lần invoke.
Billing (cao, 3-0)
